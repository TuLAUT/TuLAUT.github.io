## HSU TwinFlow: A Living Benchmark for Evaluating Data-Driven Methods for Anomaly Detection and Diagnosis in Cyber-Physical Production Systems Using Digital-Twin-Generated Data

### Description
HSU TwinFlow is a living (evolving) benchmark for evaluating data-driven methods for fault-related tasks in cyber-physical production systems (CPPS), in particular anomaly detection and fault diagnosis. Its datasets are generated by a realistic digital twin of a hypothetical production facility with several hundred components and several thousand signals, including conveyors, industrial robots, autonomous mobile robots (AMRs) and robot stations, arranged in five functional areas: goods input, singulation, AMR matrix production, parallel processing and goods output. The digital twin is implemented in Emulate3D and combines discrete-event production logic with physics-based component behavior.

The data are generated from scenario definitions, i.e. sequences of timed fault-injection and repair events, each specifying the affected component and the fault type. Each simulation run covers 60 minutes of operation sampled at 10 Hz. The first release provides training data with 0 %, 1 % and 10 % faulty time (supporting semi-supervised and unsupervised anomaly detection) and evaluation data with single-fault and two-fault scenarios for each production area, in which approximately 30 % of each sequence is faulty. Labels are given point-wise for anomaly detection and as sets of (component, fault type) tuples for diagnosis. The datasets contain measurements of all variables available in the system, so users can select arbitrary subsets of variables.

In addition to the measurements, the benchmark provides contextual data (scenario metadata, product configurations, material-flow information) and system knowledge as JSON files: the material-flow graph, the component hierarchy and the mapping from component types to applicable fault types. The GitHub repository contains the source code, knowledge graphs, scenario configurations, baseline methods, evaluation scripts and documentation; the dataset files are hosted on Zenodo.
